# 夜间铁路检修窗口排程

在有限的夜间检修窗口内，从一批候选作业中选出**总收益精确最大**的组合，
保证任意时段同时进行的作业数不超过作业队容量（`capacity`），并满足计划员
设定的**必选 / 排除**约束。

纯前端应用：**TypeScript + React + Vite**，全部计算在浏览器内完成
（求解运行在 Web Worker 中），**不调用任何在线服务、不上传数据、不附带
分析/埋点/字体/CDN 资源**。

## 数据边界（重要）

- **所有数据仅存在于本机**：导入的 JSON 只在当前浏览器页面的内存中处理；
  为了刷新后恢复工作区，界面状态（作业、约束）与最近一次成功结果会写入
  浏览器的 `localStorage`，不会离开本机。清除站点数据即可删除。
- 应用不会发起任何网络请求；静态构建产物可在完全离线环境（或
  `docker compose` 的 nginx 镜像）中运行。
- 下载的结果 JSON 由浏览器本地生成。
- **数据规模契约**：

  | 字段 | 约束 |
  | --- | --- |
  | `capacity` | 整数，`1 ≤ capacity ≤ 8` |
  | `jobs` 数量 | `1 ≤ n ≤ 50000` |
  | `id` | 唯一、非空字符串（JSON 数字会规范化为字符串） |
  | `start` / `end` | 整数，`0 ≤ start < end ≤ 1_000_000_000` |
  | `benefit` | 整数，`1 ≤ benefit ≤ 1_000_000_000` |

- 区间语义为**左闭右开** `[start, end)`；两个作业端点相接
  （`end == 下一个 start`）**不算重叠**，可由同一作业队先后承担。
- 程序不做任何“占位计算”：求解结果是模型的精确最优解，不是近似/演示数据；
  无数据时界面为空仓库状态，不生成虚构作业。

## 导入 JSON 格式

```json
{
  "capacity": 2,
  "jobs": [
    { "id": "track-inspect-a", "start": 0, "end": 120, "benefit": 30 },
    { "id": "catenary-b", "start": 120, "end": 300, "benefit": 45 },
    { "id": "signal-c", "start": 60, "end": 200, "benefit": 25 }
  ]
}
```

非法导入会**逐项列出错误**（定位到 `jobs[i].field`），并且**整个导入被
拒绝，工作区与既有结果保持不变**。允许出现契约之外的额外字段。

## 交互与约束规则

- 每个作业可设置为 **普通 / 必选 / 排除**：
  - 必选作业必须排入；排除作业任何情况下都不入选。
  - 把作业设为必选时，若其时段内必选作业的重叠数已达到 `capacity`，
    修改会被**拒绝**，旧约束、旧结果均不变（界面提示原因）。
  - 取消必选后容量立即释放，可再次设置其它必选作业。
- 结果展示：**入选集合、峰值占用（最大同时作业数）、总收益**。
- 修改约束后旧结果会标记为**已过期**；点击“重新计算”得到新的最优解。
- **计算失败不会清空最近一次成功结果**；修正约束后可直接重算。
- 页面显示的入选集合与“下载结果 JSON”中的 `selectedIds` 来自同一个数据源，
  二者严格一致。

## 求解算法（精确最优）

对作业端点做坐标压缩，在时间轴 DAG 上建立**最小费用流**：

- 时间边 `i → i+1`：容量 `capacity`（一单位流代表一条作业队轨道）；
- 作业边 `li → ri`：容量 1，费用为负；
  - 普通作业费用 `-benefit`；
  - 必选作业费用 `-(M + benefit)`，其中 `M = 候选收益总和 + 1`。
- 从时间起点向终点发送 `capacity` 单位流。

由于任意方案间的收益差都严格小于 `M`，费用最小化会**首先最大化入选必选
作业数**；当必选集合可行（最大重叠 ≤ capacity）时，最优流必然包含全部
必选作业，随后在该前提下最大化收益。费用/距离全程使用 **BigInt**，
5 万项、单项 10 亿收益下无浮点误差。

排除作业不进入网络；容量约束由时间边容量精确保证。算法只需至多
`capacity ≤ 8` 次 Dijkstra 增广（DAG 初始位势 + 约化费用），5 万作业
在现代机器上秒级完成（测试门槛 3 秒）。

## 本地开发

```bash
npm install
npm run dev       # 开发服务器
npm test          # Vitest：小规模穷举、端点语义、校验、5 万项性能
npm run build     # 类型检查 + 生产构建（产物 dist/，已在 .gitignore）
npm run verify    # tsc --noEmit + vitest run（与 Docker verify 服务一致）
```

## Docker

```bash
# 托管页面（宿主机端口可用 WEB_PORT 覆盖，默认 8080）
WEB_PORT=8080 docker compose up --build web

# 一次性验收：类型检查 + 全部测试，结束后容器退出，退出码反映结果
docker compose up --build verify
```

## 测试说明

`tests/` 使用 Vitest：

- 对 1~11 项作业、容量 1~3 的 200 组随机用例做 **2^n 全子集穷举**，
  逐一核对最优总收益、峰值占用、必选/排除合规性；
- 固定用例核对左闭右开（相接不重叠）语义；
- 必选不可行时抛出明确错误；
- 5 万作业端到端求解限时 3 秒并重算加总核对。
