# 夜间铁路检修排程器（纯前端离线应用）

在有限的夜间检修窗口内，为作业队选择**互不冲突**的检修作业组合，使总收益**精确最大化**，
并支持把作业标记为**必选**或**排除**。应用使用 TypeScript + React + Vite 构建，
全部计算在浏览器本地完成，**不调用任何在线服务、不收集任何数据**。

## 数据边界（重要）

- 所有数据（导入的作业、约束、排程结果）**只存在于浏览器内存**中：刷新或关闭页面即丢失，
  不会写入磁盘，不会发起网络请求，也没有后端、数据库或分析 SDK。
- 唯一离开页面的数据是用户主动点击 **“下载 JSON”** 后保存到本地的结果文件。
- 构建产物（`dist/`）与 `node_modules/` 已在 `.gitignore` 中排除，不进入版本库。

### 导入格式（普通 JSON）

```json
{
  "capacity": 3,
  "jobs": [
    { "id": "A-接触网检修", "start": 0, "end": 180, "benefit": 100 }
  ]
}
```

| 字段 | 约束 |
| --- | --- |
| `capacity` | 整数，`1..8`（作业队同时可进行的作业数） |
| `jobs` | 数组，长度 `1..50000` |
| `jobs[].id` | **非空**字符串，且在文件内**唯一** |
| `jobs[].start` / `jobs[].end` | 整数，`0 ≤ start < end ≤ 1,000,000,000` |
| `jobs[].benefit` | 整数，`1 ≤ benefit ≤ 1,000,000,000` |

- 区间为**左闭右开** `[start, end)`：一个作业在 `end` 时刻已结束，因此
  `[0, 2)` 与 `[2, 4)` **相接但不重叠**，capacity=1 时可同时入选。
- 字段类型必须严格匹配（如 `capacity: "2"`、`benefit: 1.5` 均为非法）。
  额外的未知字段会被忽略。
- **非法导入会被整体拒绝并逐项列出错误**（解析错误、重复 id、越界值等），
  当前工作区（作业、必选/排除约束、最近一次成功结果）原样保留。
- 合法导入会替换作业清单，并清空旧约束与旧结果（它们从属于上一批数据）。

### 导出格式（下载 JSON）

下载内容与屏幕显示的集合**来自同一份结果数据**，逐项一致：

```json
{
  "capacity": 3,
  "totalBenefit": 12345,
  "peakOccupancy": 2,
  "selectedIds": ["..."],
  "selectedJobs": [{ "id": "...", "start": 0, "end": 10, "benefit": 5 }]
}
```

## 功能说明

- 每个作业可设为 **普通 / 必选 / 排除**：
  - 必选：必须出现在排程中。若该修改会使任意时刻的必选并行数超过 `capacity`，
    **修改会被拒绝，旧约束与已有结果保持不变**，界面给出超限时刻与并行数。
  - 排除：不参与排程。
- 排程输出：**入选集合**、**峰值占用**（任意时刻最多同时进行的入选作业数）与
  **总收益**（精确整数，最大 5×10¹³，处于 JS 安全整数范围内）。
- 约束在上次成功计算之后发生变化时，结果区标注“已过期”，需点击重新计算；
  **计算失败（如必选超容量）不会清空最近一次成功结果**，修正约束后可再次重算。
- 并列最优任选其一（求解器保证返回一个最优解，不保证在并列解中的具体选择）。
- 大清单支持 id 子串过滤、按约束类型过滤与分页；5 万作业规模计算目标 **3 秒内**
  （开发机实测约 0.3–0.5 秒）。

## 算法

问题等价于“容量为 `capacity` 的带权区间调度”。求解器（`src/lib/solver.ts`）：

1. 对所有非排除作业的端点做坐标压缩；
2. 在相邻时间点之间建立容量为 `capacity`、费用为 0 的等待边，
   每个作业建立一条容量 1 的边，经过该边即表示选中该作业；
3. 从最早端点向最末端点发送恰好 `capacity` 单位流（每条流代表一条作业轨道），
   做**最小费用最大流**；
4. 费用为字典序双分量 `(必选入选数, -收益)`：先保证必选全部入选，再最大化收益。
   两个分量均为精确整数（无需 BigInt 或浮点近似），首次最短路按 DAG 拓扑序松弛，
   后续至多 `capacity−1 ≤ 7` 次增广使用 Johnson 势能 + 二叉堆 Dijkstra。
5. 必选可行性用端点事件扫描预先检查（同一时刻先结束后开始，符合左闭右开语义）。

**没有任何占位/启发式计算**：穷举测试对数百个随机小规模实例逐一比对最优值。

## 本地开发

```bash
npm install
npm run dev      # 本地开发服务器
npm test         # Vitest：穷举核对、端点语义、导入校验、5 万项性能
npm run build    # 类型检查 + 生产构建到 dist/
npm run preview  # 本地预览构建产物
```

## Docker Compose

```bash
# 托管页面，宿主机端口可用 WEB_PORT 覆盖（默认 8080）
WEB_PORT=9000 docker compose up --build web
# 然后浏览器访问 http://localhost:9000

# 一次性验收：构建镜像并运行全部测试，结束后退出（退出码即验收结论）
docker compose up --build verify
```

`verify` 服务配置为 `restart: "no"` 的一次性任务，不会常驻。

## 目录结构

```
src/
  lib/
    types.ts       数据模型
    validate.ts    导入 JSON 的严格逐项校验
    solver.ts      最小费用流精确求解器
    solver.test.ts 穷举最优值核对 / 端点语义 / 必选-排除 / 性能
    validate.test.ts
  ui/
    App.tsx        状态管理：导入、约束编辑、重算、结果保留
    JobTable.tsx   作业清单与约束切换（分页/过滤）
    ResultPanel.tsx 结果展示与下载（与屏幕一致）
```
